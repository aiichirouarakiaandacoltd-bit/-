## 0．最優先原則（すべての処理の前に確認）
1. **本システムの成果物は、Claude塾の内部学習教材専用とする。外部への公開・配布・共有は一切行わない**
2. **人物の画像を最大限多く使い、視聴者を飽きさせない。** 内容に合った実写映像・写真を可能な限り多く確保し、同じ画面の繰り返しや単調な図解を減らして、画面を華やかにする（第4-2章）。素材を大量に集めること自体を目的にしない
3. **事実が確認できないものは動画に入れない。** 推測で補わない
4. **写っている人物・行事を特定できない画像は使わない**
5. 未確認・不足があれば完成と呼ばない。不足事項・理由・必要な対応を報告して停止する
6. 縦型版と横型版で、同じ行事・出来事を重複して制作しない
7. 優先順位：①荒木の明示指示 ②本書 ③矛盾しない承認済みの個別指示

## 0-2．作業前チェック（毎回、制作の最初に実行する）
以下を上から順に確認し、足りないものは自分で準備する。準備できない場合は、原因と必要な対応を報告して停止する。結果は `projects/<制作番号>/env_check.md` に記録する。

**① 必要なツールの確認とインストール**
- 確認するもの：Python 3、ffmpeg（ffprobeを含む）、Pythonライブラリ（requests、Pillow、gdown）
- 不足していれば、OSに合った公式の方法（brew／apt／winget／pip）でインストールする
- 本書に記載したツール・ライブラリ・フォント・VOICEVOXのインストールは、荒木が事前に許可済み。チャットで確認を求めずに実行する
- インストール後に、バージョンを表示して動作を確認する

**② VOICEVOXへの接続**
- `http://localhost:50021/version` に接続できるか確認する
- 接続できなければ、VOICEVOXエンジンを起動する。未導入なら公式配布元（voicevox.hiroshiba.jp またはDockerイメージ voicevox/voicevox_engine）から導入して起動する
- 話者IDは決め打ちせず、`/speakers` の一覧から「青山龍星」の「ノーマル」のIDを取得して使う
- 速度は `speedScale: 0.90` を指定する
- 短い試験音声を1つ生成し、正常に再生できることを確認する

**③ BGMをGoogleドライブから取得**
- 取得元：https://drive.google.com/file/d/1NI_d0oPaY1N1QrG1F9MeKY0T7S29Rh9N/view?usp=drive_link
- ファイルID `1NI_d0oPaY1N1QrG1F9MeKY0T7S29Rh9N` を gdown で取得し、`assets/bgm/` に保存する
- すでに同じファイルがあれば、再取得しない
- 取得できない場合（共有設定が「リンクを知っている全員」になっていない等）は、荒木に共有設定の確認を依頼して停止する
- ffprobeで再生時間と形式を確認する

**④ フォント：Noto Sans JP**
- 字幕・表紙画像・人物名など、画面上のすべての文字は **Noto Sans JP（太字はBold）** で制作する。他のフォントへの置き換えは禁止
- `fc-list | grep "Noto Sans JP"` などで導入済みか確認する
- 未導入なら、公式配布元（Google Fonts または github.com/notofonts）から取得してインストールする
- ffmpegで字幕を焼き込む場合は、フォントファイルのパスを直接指定する
- Noto Sans JPを用意できない場合は、制作を開始せず停止する

## 1．対象と方針
- 主対象：55歳以上、特に65歳以上の女性
- 基本構造：**人物 × 具体的な出来事 × 明確な疑問 × 事実による回答**
- 1本につき中心テーマは1つ。冒頭で示した疑問は必ず本編で回答する
- 優先題材：愛子さまの具体的な出来事、両陛下の交流、海外王室との交流、公務、装い、所作、歴史的背景
- 制度の解説は、実在する人物・出来事を入口にして行う

**構成の型（第1-3章の優先企画型。A型＞B型＞C型）**
- A型｜行事×一場面×疑問：実際に何が起きたかを映像と事実で説明する（最優先）
- B型｜人物×過去の出来事×現在の背景：確認できる時系列で構成する（第2優先）
- C型｜同種の出来事×異なる対応×理由：比較の条件をそろえ、人物の優劣をつくらない（条件付き）

**禁止：** 架空の発言・内心描写。根拠のない対立・不公平・病気・私生活・血統疑惑の捏造や断定。誤解を誘う情報の出し惜しみ。敬称は宮内庁の表記に従う。

## 1-2．動画の設計式【荒木指示 2026-11-23 追加・最重要】
**すべての動画を「強い疑問 × 確認できる事実 × 人物の物語 × 比較 × 独自の解説」で設計する。揶揄・対立はNG。**
5つの要素は企画（G0）・台本（G3）・タイトル（G6）のすべてで満たす。1つでも欠ける企画は出さない。

| 要素 | 満たす条件 | 例 |
|---|---|---|
| ①強い疑問 | 冒頭2秒で「なぜ？」「何を？」と思わせ、本編で必ず答える。答えは事実で出せるものに限る | 「文化勲章は、どこで誰が手渡すのか？」 |
| ②確認できる事実 | 答えの根拠は宮内庁等の公式記録（第2章G1）。推測・伝聞・未確認の逸話で答えない | 宮内庁の写真説明・ご日程・おことば全文 |
| ③人物の物語 | 出来事の羅列にせず、主役の方の歩み・想い（公式に語られたもの）・積み重ねとしてつなぐ | 祖父母・両親から受け継がれた交流をたどる |
| ④比較 | **事実と事実を並べる比較だけ**を使う（下記）。比べた結果は事実で示し、優劣の評価はしない | 「前回の訪問」と「今回」、「文化勲章」と「秋の勲章」 |
| ⑤独自の解説 | 公式記録を整理して、視聴者が知らない背景・制度・意味を当チャンネルの言葉で説明する。解説は「分析」と分かる言い方にし、事実と混ぜない | 「親授式」と「伝達式」の違いの説明 |

**使ってよい比較（事実×事実）**
- 時間の比較：前年・前回・過去の同じ行事と今回（日数・訪問先の数・行事の内容）
- 制度・行事の比較：例）文化勲章と秋の勲章、国賓と公式実務訪問賓客、親授式と伝達式
- 歴史の比較：先例（初めて・〇年ぶり等）。公式記録で確認できるものに限る
- 同じ方の歩みの比較：例）初めてのご公務と今回

**揶揄・対立のNG（企画・台本・タイトル・表紙・説明文のすべてで禁止）**
- 皇族同士を比べて優劣・格差・扱いの差を示すこと（例：「〇〇家との違い」「格の違い」「対応の差」）
- 表情・視線・立ち位置から内心や不仲を読み取ること（例：「その表情に注目」「本心に気づいた」）
- 怒り・嫉妬・確執・冷遇・押しのけた等の対立の描写、知事・政治家・国民の「激怒」「拒否」などの創作
- 皮肉・あおり・嘲笑の言い方、絵文字での揶揄（🙄等）、政治的主張
- 競合でこの型が伸びていても、題材・型として採用しない（第2章R2）

**採点と停止：** G0企画評価・決まりの確認係の採点で5要素を1つずつ確認する。NGに当たる表現が1つでもあれば不合格とし、直してから次へ進む。タイトル・説明文本文・ナレーションはNG語の自動検査（第8章・第9章）も行う。

## 1-3．競合調査と企画の型【荒木指示 2026-11-23 追加】

### 1-3-1．競合の範囲と役割
| 区分 | チャンネル | 参考にする役割 |
|---|---|---|
| 長尺・重点 | 皇室栄華 | 園遊会・訪問の具体場面 |
| 長尺・重点 | 皇室のお話 | 外交・晩餐会・対応差 |
| 長尺・重点 | みんなの皇室 | 強い疑問・実在する問題提起 |
| 長尺・重点 | それいけ皇室 | 人物物語・時系列 |
| 長尺・追加調査 | 皇室物語ストーリー／皇室という光／皇室の歩み／皇室Japan | 追加で調べる |
| Shorts・重点 | 皇室の素晴らしい物語 | 一場面・冒頭 |
| Shorts・重点 | 皇室ヴェール | 所作・交流 |
| Shorts・重点 | JAPANの皇室 | 視覚的な行動 |
| Shorts・追加 | 天皇御一家の素晴らしさ／皇室のお話 | 追加で調べる |
| 保留 | 皇室の夢【海外の反応】 | 成長報告はあるが直近長尺の個別実績が不足。長尺の成功モデルとしては保留 |

**調査時点の参考例（2026-11-23時点・荒木提供）：** 皇室栄華は園遊会 約27万回、青森訪問 約7万・約5.7万回に対し、別題材 約6,600回。皇室のお話には過去の外交・晩餐会の高再生例と直近の低再生例がある。皇室ヴェールには100万回超のShorts例がある。**公開経過日数をそろえていないため、因果関係と直近の再現性は未確定。**

### 1-3-2．比較・採用の方法
- 競合を **大手／新規／少登録者の高再生／低再生** に区分する。原則 **直近10本**、必要な時は **30本** を確認する。
- 確認項目：動画URL・公開日・調査日時・尺・形式・再生数・経過日数・登録者比・直近10/30本の平均と中央値・上位/下位各3本・人物・出来事・タイトル・サムネイル・冒頭・構成・コメント・素材依存度・権利・制作負荷。CTR・平均視聴時間・冒頭離脱は取得できる場合のみ。
- 可能なら **公開後7日など同じ経過期間** で比べる。取得できない値は「未確認」と書く。
- 高再生の動画は **クリックと継続の理由** を、低再生の動画は **人物の需要・題材の抽象性・公開条件** を検証する。**公開されていないCTRを推測で確定しない。**
- 手順：**模倣 → 要素分解 → 本質の言語化 → 独自企画化。** 競合のタイトル・台本・映像はコピーしない。

### 1-3-3．優先企画型
| 型 | 優先度 | 組み立て | 例 |
|---|---|---|---|
| **A型** | **最優先** | **行事 × 一場面 × 疑問**。実際に何が起きたかを映像と事実で説明する | 園遊会、外国賓客、晩餐会、海外・地方訪問 |
| **B型** | 第2優先 | **人物 × 過去の出来事 × 現在の背景**。確認できる時系列で構成する | 雅子さまの交流、愛子さまの公務、両陛下の歩み |
| **C型** | 条件付き | **同種の出来事 × 異なる対応 × 理由**。比較の条件をそろえ、人物の優劣をつくらない（第1-2章の揶揄・対立NG） | 外交儀礼、装い、公務 |

**優先人物：** ①愛子さま・雅子さま ②両陛下・佳子さまの具体的な活動 ③美智子さま・紀子さま・悠仁さまは出来事ごとに判断 ④久子さま・華子さま・信子さまは単独の需要が未確認のため検証枠。**競合が少ない＝需要がある、とは扱わない。**

**発注しない題材：** 「宮家の創設と女性皇族の役割」のような広い制度解説は、主役・具体的な出来事・疑問を絞れない限り発注しない。制度は人物・出来事を入口に説明する。

**禁止（再掲）：** 架空の発言・内心・対立・不公平・病気・私生活・血統疑惑の捏造や断定。敬称は宮内庁の表記を基準とする。

### 1-3-4．タイトルと視聴設計
**強い疑問でクリック → 具体的な事実と人物で継続 → 実写素材と独自の解説で理解 → 回答・納得 → 登録・関連視聴へ。**
- 疑問は動画の中で必ず回収する。
- 根拠のない「激怒」「冷遇」などで刺激をつくらない（第1-2章のNG語は自動検査）。

**G1 事実確認：** 宮内庁→官公庁→主催者公式→主要報道→史料の順で、人物・敬称・日時・場所・発言・引用・制度を照合する。各事実について「公式事実／報道／分析」を区別し、出典URLを記録する。

**G0 企画評価（内部用・100点）：** 学習者への適合10／**強い疑問20**／**確認できる事実15**／**人物の物語15**／**比較10**（事実×事実）／**独自の解説10**／**人物画像・実写素材の豊富さ15**（内容に合う素材の量と多様さ。量だけで加点しない）／シリーズ性5。80点以上で候補、85点以上を優先する。**第1-2章の5要素のどれかが0点、または揶揄・対立に当たる企画は点数に関係なく不採用**。

## 3．人物画像の収集ルール
**収集先の例：** 宮内庁ウェブサイト、官公庁・自治体・主催者の公式サイト、主要報道機関の記事写真、Wikimedia Commons、公的な写真アーカイブ

- 1本の題材につき、登場する全人物・全行事の画像をできる限り多く集める
- 同じ行事でも、角度・距離・瞬間の異なる写真を優先して集める
- 解像度の高い画像を優先する（目安：横型版は長辺1920px以上、縦型版は長辺1080px以上）
- **人物・行事の特定：** 掲載元のキャプション・記事本文で、誰が・いつ・どこで写っているかを確認できた画像だけを使う。人物を取り違えないことを最優先する
- 収集時のマナー：短時間に大量のアクセスをしない。ログインが必要なページや有料の記事には立ち入らない
- 保存先：`assets/<制作番号>/`
- **ページ選びの自動化（2026-11-21）：** `bin/kabu run images --auto <人物名> --months <YYYYMM…>` で、宮内庁の月別ご日程から人物名が載る写真ページを選んで収集する
- ページ末尾に説明文が1つだけの写真は、台帳の「確認方法」を「ページ説明文（要目視）」として入れ、当てっこ係がお顔で照合して「目視確認済」にしたものだけ使う（要目視のまま使うとG5で不合格）

- 写真だけでなく、人物・行事を確認できる**実写映像**（宮内庁・官公庁・主催者の公式動画など）も収集対象とする
- 1つの場面（章）につき、内容に合う候補を3点以上集めることを目安にする（寄り・引き・別の瞬間）

**ledger.csv の列：** 番号／ファイル名／取得元URL／掲載サイト名／取得日／写っている人物／撮影日・場所・行事／確認したキャプション／確認方法（キャプション・ページ説明文（要目視）・目視確認済）／使用する場面／素材種別（写真・映像）

## 4．人物画像の見せ方【最重要】
**基本方針：画面には常に人物がいる状態を目指し、同じ絵が長く続かないようにする。**

| 項目 | 縦型版 | 横型版 |
|---|---|---|
| 画像の切替間隔 | 2〜4秒 | 4〜6秒 |
| 1枚の最長表示 | 5秒 | 8秒 |
| 人物が映る時間の割合 | 95%以上 | 90%以上 |
| 使用カット数の目標 | 15〜25 | 100〜150 |
| 異なる画像の目標枚数 | 12枚以上 | 60枚以上 |

- すべての静止画に**少しの**拡大・移動（パン）を付け、静止したままにしない。**無理に動かさない**：ズームは2〜7%、パンはごく小さく、写真の外側（隙間・引き伸ばし）を決して見せない。写真を横にずらして主役を中央に寄せることはしない（荒木指示 2026-11-22）
- **ズーム・パンは、主役の人物を画面の真ん中に配置した状態から始める**（荒木指示 2026-11-21）。主役の位置は当てっこ係が点検シート（`bin/kabu run focus`、格子と顔検出の座標つき）を見て `projects/<制作番号>/focus.json` に登録する（未登録はG5で不合格）。人物名が複数の場面は、表示する方々の中心を真ん中にする
- 同じ画像を再使用するときは、全身→顔の寄り→手元や装いなど、トリミングと動きを変える。**同じ画像は、縦型（ショート）では1本につき1回だけ（再使用禁止。荒木指示 2026-11-22）**、横型は3回まで
- 人物が登場するたびに名前を字幕で表示する（例：「天皇陛下」「愛子さま」）
- 撮影の日付・場所・行事名を、画面の隅に小さく表示する
- 比較の場面では左右に並べ、それぞれの人物名を表示する
- 図解・地図・年表は最小限にし、可能なら人物写真を重ねる
- 次の章に移るときは、新しい人物画像から始める

## 4-2．素材の豊富さと画面の華やかさ【重要】
**基本方針：動画の内容に合った実写映像・写真を可能な限り多く確保し、同じ画面の繰り返しや単調な図解を減らす。素材を大量に集めること自体を目的にしない。**

- **内容に合うことが前提：** ナレーションの内容（その場面の人物・行事・瞬間）と一致する素材だけを使う。尺を埋めるための無関係な素材・水増しは使わない
- **実写を優先：** 実写映像 → 実写写真 → 図解の順に優先する。実写映像は人物・行事を確認できる公式動画などに限り、使う区間を `scenes.json` に記録する
- **同じ画面を繰り返さない：** 隣り合うカットに同じ画像を使わない（1つの場面が長いときは、同じ行事の別の写真に切り替える）。同じ画像は1本につき3回まで（第4章）
- **多様さの目安：** 異なる画像の数 ÷ カット数 を、縦型0.6以上・横型0.5以上にする
- **単調な図解を減らす：** 図解・地図・年表・文字だけの画面は、縦型で合計3秒以内、横型で全体の5%以内。使う場合も人物写真を重ねる
- **観戦・ご覧の場面：** 競技・大会などは、会場全体の写真と、観戦しているお姿の写真の**両方**を使う（荒木指示 2026-11-21）。ページ末尾の説明文1つで複数の写真を紹介している場合は、その説明文に名前のある方をお顔で照合して使い、台帳にその旨を記す
- **華やかさ：** 装い・会場・花・沿道の人々の表情など、行事の雰囲気が伝わる実写を選ぶ。引き（全体）と寄り（表情・手元）を交互に並べ、章の冒頭は新しい素材から始める
- 華やかさのために、AIによる人物の生成・着色・合成は行わない（下記の禁止事項）

**画像で禁止すること：** AIによる実在人物の顔の生成・合成・表情の変更、着色、体型の変更。許される加工は、トリミング・拡大縮小・パン・明るさの軽い補正だけとする。

## 5．固定仕様
| 項目 | 縦型版 | 横型版 |
|---|---|---|
| 尺 | 59秒以内（推奨50〜57秒） | 9〜10分（題材により8〜12分。12分超は荒木が個別判断） |
| 画面 | 9:16／1080×1920 | 16:9／1920×1080 |
| fps | 30 | 30 |

**縦型版の構成：** 0〜3秒 核心の人物と疑問／3〜15秒 状況／15〜40秒 展開・根拠／40〜57秒 回答
**横型版の構成：** 0〜10秒 疑問と具体的な場面／10〜30秒 この動画で分かること／本編 背景→検証→回答→納得。60〜90秒ごとに新しい情報か人物を出す（水増しは禁止）

**音声：** VOICEVOX「青山龍星」、速度0.90。クレジット「VOICEVOX:青山龍星」を表示する
**字幕：** 原則として全文を表示。必ずNoto Sans JP Bold、白文字＋黒縁。**文字は最大限大きく：縦型は1行7字・140px（画面の高さ66%の位置）、横型は1行13字・130px**、最大2行（荒木指示 2026-11-21：視聴者の中心は55歳以上、特に65歳以上の女性）。読点も1字と数え、画面からはみ出す行だけ自動で縮める。**改行は文節（言葉のまとまり）の切れ目だけで行い、言葉の途中・数字と単位（「11月17日」など）の間では改行しない**。**字幕は最大限の大きさにしつつ、画面から決してはみ出さない**（左右30pxの余白と縁取りを含めて画面幅に収める。G5で全行の幅を実測し、はみ出しがあれば不合格）
**人物名・撮影情報の表示：** 極力小さくする（縦型：人物名32px・撮影情報22px、横型：30px・20px）。字幕を画面の主役にするため（荒木指示 2026-11-21）
**BGM：** UNL1337（箕輪レコーズ）。第0-2章③で `assets/bgm/` に取得したファイルを使う
- ナレーション中は、BGMを十分に下げる（目安：ナレーションより18〜24dB低く）

**表紙画像：** 実在人物の写真1〜2人、短い疑問文を大きな文字で。濃紺#16243A／金#D8BC72／白#FFFFFF。赤は使わない
**書き出し：** MP4／H.264／AAC

## 6．出力ファイル
`projects/<制作番号>/` に以下を出力する。
- `plan.md`：企画（G0）
- `facts.md`：事実と出典
- `ledger.csv`：画像台帳
- `script.md`：章ごとの完成ナレーション全文
- `scenes.json`：場面設計（下記）
- `output/<制作番号>_<縦型|横型>_internal.mp4`
- `qa_report.md`：検査結果

**scenes.json の1場面の項目**
```
{
  "scene": "03-2",
  "start": "0:42", "end": "0:47",
  "narration": "この場面の完成ナレーション",
  "subtitle": ["1行目", "2行目"],
  "image": "A015", "crop": "顔の寄り", "motion": "ゆっくり拡大",
  "images": ["A015", "A016"],  // 場面が長く複数カットになる場合の切替素材（隣り合うカットで同じ画像にしない）
  "clip": {"start": 12.0},  // 素材が実写映像のときだけ：使う区間の開始秒
  "person_label": "愛子さま",
  "caption": "2025年○月 ○○にて"
}
```
- 章・場面ごとに、ナレーションと画像と演出を同じ場所に置く
- 「前と同じ」「台帳参照」「以下同様」の省略は禁止。必要な情報は、使う場面ごとに書く
- ナレーションは冒頭から結末まで省略しない

## 7．停止条件
次のいずれかに当てはまる場合は、生成を止めて報告する。
- 確認できない主要な事実が残っている
- 写っている人物・行事を特定できない画像しか集まらない場面がある
- 人物画像が目標の70%未満にとどまる
- 内容に合う素材が足りず、同じ画面の繰り返しや図解でしか尺を埋められない
- 尺が仕様から外れ、ナレーションを削ると内容が成り立たない
- G0（タイトル・概要）の承認がない

※G0の承認後は承認を求めない。上記の停止条件（事実・画像の不足など）に当たった場合だけ止めて報告する。これは承認の依頼ではなく、本書第0章5の「未確認・不足があれば完成と呼ばない」による報告である

## 8．完成判定（G5 自動検査）
すべて満たした場合のみ「完成」とする。
- [ ] 人物・日付・敬称・引用が `facts.md` と一致している
- [ ] 画像の人物名・撮影情報が `ledger.csv` のキャプション確認と一致している
- [ ] ナレーション全文と字幕が一致し、誤字がない
- [ ] 尺・解像度・fps・形式が仕様どおりになっている
- [ ] 画面上のすべての文字がNoto Sans JPで表示されている
- [ ] 字幕が最大限の大きさで、画面からはみ出していない
- [ ] ナレーションが青山龍星・速度0.90で生成されている
- [ ] 第4章の切替間隔・最長表示・人物の割合・同一画像の回数を満たしている
- [ ] 第4-2章：隣り合うカットに同じ画像がない／異なる画像÷カット数が目安以上／図解・文字だけの画面が上限以内
- [ ] 音声と映像の長さが一致し（終盤で音が途切れない）、黒画面・無音・音割れがなく、BGMの音量が適切で、不自然なカットがない
- [ ] 冒頭の疑問に本編で回答している
- [ ] 揶揄・対立のNG語がナレーション・人物名にない（第1-2章。自動検査）

`qa_report.md` には、項目ごとの合否、実測値（尺・カット数・異なる画像の枚数・人物が映る割合・実写映像の数・図解の秒数）、不足事項と対応案を記載する。

## 9．公開用テキスト（タイトル・表紙見出し・説明文）【荒木指示 2026-11-21 追加】
G5の完成判定に合格した後、次の順に作る（G6）。タイトルはG0で承認済みのものを使う。公開・投稿は荒木が判断し、システムは投稿しない。

**① タイトル（タイトル係）**
- CTR20%以上を狙う。**99文字以内・ハッシュタグ付き**（例：`【この秋の愛子さま】どこを訪ねられた？… #愛子さま #皇室`）
- 型：【導入】＋短い疑問文＋具体語（地名・行事・人物）＋根拠の示唆（宮内庁の記録から等）＋ハッシュタグ2〜4個
- 事実確認済みの内容だけで作る。誇張・煽り・皇族間の比較や対立・未確認の逸話は使わない。強い疑問を入れ、揶揄・対立のNG（第1-2章）に当たる言葉は使わない（`publish_text` がNG語を自動検査）
- CTR20%は目標値であり保証ではない。公開後に分析係が実測し、型の分析係が型を見直す
- **出力：テキストボックス（コードブロック）で、一括コピーできる形で提示する**

**② 表紙の3段見出しと中心画像（タイトル係→デザイナー(重要)）**
- 3段（上段・中段・下段）の見出しは、**確定したタイトルの文言から流用する**（タイトルに無い言葉を足さない）
- 中心となる画像（台帳番号）をここで確定し、`publish.yaml` の `thumb.center_image` に記録する。表紙の仕様は第5章どおり
- 表紙の作成：`bin/kabu run thumb_render` で切り抜きとCanvaの操作計画（`thumb/canva_plan.json`、中段は1行に収まる文字サイズ）を作り、デザイナー(重要)が計画どおりにCanvaを操作して書き出し、`python -m pipeline.thumb_canva --fetch` で保存・検査する

**③ 説明文（説明文係）**
- タイトルから作る。**`templates/description_template.md` をお手本どおりの構成で使う**：冒頭タイトル→本文（疑問→時系列の事実→動画の案内→未確認情報の区別）→問いかけ→チャンネル案内→【参考資料】→【画像クレジット】→【制作クレジット】→【免責事項・重要事項】（全項目）→【著作権について】→【素材提供元】→【情報の利用と責任について】→【訂正・削除・権利関係のお問い合わせ】→【ハッシュタグ】
- **画像クレジット・免責事項はすべてフルバージョンで掲載し、省略しない**
- **マークダウン記号（`**` 太字・`#`/`##` 見出し）は使わない**（YouTubeの説明欄では装飾にならず文字のまま表示されるため。荒木指示 2026-11-21）。見出しは【】と■で示す。ハッシュタグの#は使う
- 【ハッシュタグ】は**カンマ区切り。最後のハッシュタグの後ろにもカンマを付ける**
- **説明文は5000文字以内、ハッシュタグは多め**にする（荒木指示 2026-11-21）。ただし**タイトル込み・重複を除いて60個まで**（61個以上あるとYouTubeが全てのハッシュタグを無視するため）。人物・行事・地名・施設・皇室一般・チャンネル名から、内容に合うものだけを選ぶ
- **出力：テキストボックス（コードブロック）で、一括コピーできる形で提示する**
- `python -m pipeline.publish_text --project <制作番号>` で組み立てと検査を行う（タイトル99文字以内・ハッシュタグ有無・表紙3段がタイトル内にあるか・中心画像の確定・末尾カンマ・未置換の項目・5000文字以内）
- 出力ファイル：`projects/<制作番号>/publish.yaml`（材料）、`publish/title.txt`、`publish/description.txt`、`publish/check.md`

**④ CTRの実測（G7・公開後／分析係）**
- 公開後、分析係がCTR・インプレッション・再生数を実測し、`bin/kabu run ctr --video-id <ID> --ctr <CTR%> …` で `data/ctr_log.csv` に記録する。`data/ctr_report.md` にタイトルの型ごとの平均と目標20%以上の本数を出し、型の分析係が型を見直す
