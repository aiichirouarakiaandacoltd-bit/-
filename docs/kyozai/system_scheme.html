19工程: 誰が、何を、どこに書くか

工程は bin/kabu の状態ファイル(state.json)で管理します。種類は「係」=AIが判断、「点検」=採点の係、「機械」=道具が自動処理、「承認」=荒木さん。

工程担当種類内容と出力不合格の戻り先

係の一覧: 16のサブエージェント

各係は .claude/agents/*.md に役割と使える道具が定義されています。人物は「お顔」で見分けず、宮内庁の説明文・人数・服装で照合するのが全係共通の決まりです。

動画の設計式: 5つの要素が1つでも欠ければ出さない

「強い疑問 × 確認できる事実 × 人物の物語 × 比較 × 独自の解説」。企画(G0)・台本(G3)・タイトル(G6)のすべてで満たします。

要素満たす条件例

使ってよい比較(事実×事実だけ)

  • 時間: 前回・前年の同じ行事と今回
  • 制度・行事: 文化勲章と秋の勲章、親授式と伝達式
  • 歴史: 初めて・〇年ぶり(公式記録で確認できるもの)
  • 同じ方の歩み: 初めてのご公務と今回

締めくくり(必須)

  1. まとめ: 冒頭の疑問の答えを一文で
  2. 意味づけ: 「〜かもしれません」と分析と分かる言い方で
  3. 問いかけ: 選んで答えやすい具体的な問い
  4. お願い: コメントのお願い、最後に約2秒の余韻

「答えは〜」の前には、冒頭の疑問を言い直す前置きを必ず入れる。ナレーションは「です・ます」調で統一。

揶揄・対立のNG(企画・台本・タイトル・表紙・説明文すべて)

  • 皇族同士を比べて優劣・格差・扱いの差を示す
  • 表情・視線・立ち位置から内心や不仲を読み取る
  • 怒り・嫉妬・確執・冷遇などの描写、「激怒」「拒否」などの創作
  • 皮肉・あおり・嘲笑、絵文字での揶揄、政治的主張
  • 作られた発言(公式記録にない「」の台詞)、汗・怒りマーク、赤丸
  • 競合で伸びていても、この型は採用しない

NG語はタイトル・説明文・ナレーションで自動検査。1つでもあれば不合格。

企画の型: 1本=1場面=1つの疑問

企画係は最新動向(R1)と競合調査(R2)から題材を決めます。競合は「模倣→要素分解→本質の言語化→独自企画化」で学び、タイトル・台本・映像はコピーしません。

最優先A型

行事 × 一場面 × 疑問。実際に何が起きたかを事実で説明(園遊会・外国賓客・晩餐会・訪問)

第2優先B型

人物 × 過去の出来事 × 現在の背景。確認できる時系列で構成(雅子さまの交流・愛子さまの公務)

条件付きC型

同種の出来事 × 異なる対応 × 理由。条件をそろえ、人物の優劣をつくらない

競合調査で分かった「伸びる要因」

    優先人物

    1. 愛子さま・雅子さま
    2. 両陛下・佳子さまの具体的な活動
    3. 美智子さま・紀子さま・悠仁さま(出来事ごとに判断)
    4. 久子さま・華子さま・信子さま(検証枠)

    日本称賛の要素は「事実で言える海外からの敬意」に置き換える

    名前を冠した花・名誉学位・勲章・記念植樹、相手国元首のスピーチの一節(一字一句)、宮中のおもてなしの作法、語学と国際経験、長く続く交流。「世界が絶句」「仰天」など相手の内心の断定は使わない。

    G0の企画評価(100点・内部用)

    学習者への適合10/強い疑問20/確認できる事実15/人物の物語15/比較10/独自の解説10/人物画像・実写素材の豊富さ15 ほか。複数本はバッチ(research/batches/*.yaml)でまとめて承認し、1本終わると次の本へ自動で進む。

    画像のルール: 常に人物がいて、語っているものが映る

    写真は宮内庁・官公庁・主催者・主要報道・Wikimedia Commons から、誰が・いつ・どこでをキャプションで確認できたものだけ。台帳 ledger.csv に1枚ずつ記録します。

    項目縦型(ショート)横型(長尺)

    見せ方

    • すべての写真に少しの拡大・移動(ズーム2〜7%)。写真の外側は見せない
    • ズーム・パンは主役を画面の真ん中に置いた状態から始める(主役位置は当てっこ係が focus.json に登録)
    • 人物名を毎回表示、撮影日・場所・行事を画面の隅に小さく
    • 複数の方が写る横長写真は横幅いっぱいに置き、上下にぼかした背景
    • 縦型は画面を上(名前・撮影情報)・中(写真)・下(字幕)に分け、画像と文字を重ねない
    • 過去の会見を扱う時は確認済みの近年の写真を使ってよい。実際の撮影日を必ず表示し、「その年の写真」と誤解させない
    • 写真の切り替えは字幕の切れ目で(語の途中で替えない)

    ナレーションと画像の一致(最重要)

    語っている「もの・人・場所・瞬間」をその場面の画像で見せる。優先順位は ①その瞬間の写真 ②同じ物・場所の写真(日付を表示) ③その人物のその行事の写真 ④イメージ写真(「イメージ」と表示)。各場面の scenes.json に一致の理由 match を書く。

    禁止

    AIによる実在人物の顔の生成・合成・表情の変更、着色、体型の変更。許される加工はトリミング・拡大縮小・パン・明るさの軽い補正だけ。報道・YouTubeの映像は取り込まない(権利と利用条件を確認できた公式映像のみ)。

    固定仕様: 声・字幕・音・色はすべての動画で同じ

    項目仕様

    長尺(横型)の追加ルール

    ショートの決まりはすべて長尺にも当てはめたうえで、次を足します。

      完成判定(G5): 全項目合格のときだけ「完成」

      道具 pipeline/qa_rules.py が自動で測り、qa_report.md に合否と実測値を書きます。そのあと当てっこ係が書き出し後のコマを目で点検します。

        タイトル・表紙・説明文(G6)

        ① タイトル

        CTR20%以上を狙う。99文字以内・ハッシュタグ2〜4個。型は【導入】+短い疑問文+具体語+根拠の示唆。G0で承認済みの題名を使い、事実と合わない所だけ最小限に直して完成報告で伝える。長尺はA/B/Cの3案でABテスト。

        ② 表紙

        3段見出しはタイトルの文言から流用(足さない)。濃紺・金・白、赤なし。ショートはCanvaでパターンA(バランス型)とB(上寄せ型)の2枚、同じ写真。長尺は型R(1名)/型D(2名)で3枚、写真・構図・人物の左右・題名の位置を3枚とも変える。

        ③ 説明文

        テンプレートどおり: 本文→問いかけ(動画の締めと同じ)→参考資料→画像クレジット→制作クレジット→免責事項(省略しない)。5000文字以内、マークダウン記号なし、ハッシュタグはカンマ区切りで最後にもカンマ、60個まで。長尺は章の時刻入り。

        表紙の写真の決まり(荒木さんの指摘から追加)

          ④ 公開後(G7)は分析係がCTR・再生数を実測して記録し、型の分析係が月1回、型を見直します。公開・投稿はシステムでは行いません。

          停止条件: 足りなければ「完成」と呼ばず止まって報告

          • 確認できない主要な事実が残っている
          • 写っている人物・行事を特定できない画像しか集まらない場面がある
          • 人物画像が目標の70%未満
          • 内容に合う素材が足りず、繰り返しや図解でしか尺を埋められない
          • 尺が仕様から外れ、ナレーションを削ると内容が成り立たない
          • G0の承認がない

          最優先原則

          1. 成果物は内部学習教材専用、外部に公開・配布しない
          2. 人物の画像を最大限多く使い、飽きさせない
          3. 事実が確認できないものは入れない(推測で補わない)
          4. 人物・行事を特定できない画像は使わない
          5. 未確認・不足があれば完成と呼ばない
          6. 縦型と横型で同じ出来事を重複して作らない

          優先順位: ①荒木さんの明示指示 ②制作ルール ③矛盾しない承認済みの個別指示。点検係の判定は上書きせず、直しは「再採点」として追記する。

          ファイルと道具

          1本ごとのフォルダ projects/<制作番号>/

          司令塔 bin/kabu

          主な道具 pipeline/

          画面の設計図: 文字と写真を重ねない配置

          ショート本編・ショート表紙(パターンA/B)・長尺表紙を、実寸の比率で描いています(数字はピクセルの目安)。

          データの流れ: どのファイルが次の工程の材料になるか

          細則: 各工程の具体的な決まり

          作業前チェック(毎回最初)

          1. ツール: Python 3・ffmpeg/ffprobe・requests・Pillow・gdown。無ければ公式の方法で入れる(荒木さん許可済み)
          2. VOICEVOX: localhost:50021 に接続、話者IDは /speakers から「青山龍星 ノーマル」を取得、試験音声を1つ作る
          3. BGM: Googleドライブから gdown で assets/bgm/ に取得(あれば再取得しない)
          4. フォント: Noto Sans JP を確認。用意できなければ制作を始めない

          G0 で荒木さんに出すもの(plan.md)

          1. 題材と判断理由(最新動向・競合の伸びとの対応)
          2. タイトル(99字以内・#付き)
          3. 概要(疑問・答えの要旨・型・写真の当て・尺)
          4. 5要素の表
          5. 100点評価: 適合10/強い疑問20/事実15/物語15/比較10/解説10/素材15/シリーズ性5。80点以上で候補、85点以上を優先。5要素のどれかが0点か揶揄・対立なら不採用

          G1 事実確認の順序

          宮内庁 → 官公庁 → 主催者公式 → 主要報道 → 史料。人物・敬称・日時・場所・発言・引用・制度を照合し、1つずつ「公式事実/報道/分析」を区別して出典URLを残す。引用は一字一句、原文の文脈を変える切り取りはしない。

          画像台帳 ledger.csv の列

          番号/ファイル名/取得元URL/掲載サイト名/取得日/写っている人物/撮影日・場所・行事/確認したキャプション/確認方法(キャプション・ページ説明文(要目視)・目視確認済)/使用する場面/素材種別。説明文が1つしかないページの写真は「要目視」とし、当てっこ係が説明文・人数・服装で照合して「目視確認済」にしたものだけ使う。

          scenes.json の1場面

          scene 番号・start/end・narration(完成ナレーション)・subtitle(行ごと)・image/images(台帳番号)・crop(顔の寄り/全身など)・motion・person_label(人物名)・caption(撮影情報)・subject・match(言葉と画像が合う理由)。「前と同じ」「以下同様」の省略は禁止。

          字幕の細則

          • 改行は文節の切れ目だけ。言葉の途中、数字と単位の間では切らない
          • 「ました」「です」など語尾だけの行はつくらない
          • 句点と行末の読点は省いてよい(行の途中の読点は残す)
          • 長い行を自動で縮めない(大きさがそろわなくなるため)
          • G5で全行の幅・大きさ・書式を実測し、1つでも違えば不合格

          文体と表記

          • ナレーションは「です・ます」調。引用は原文のまま
          • 表記は1本の中でタイトル・表紙・字幕・説明文までそろえる(迷う語は漢字)
          • 意味が変わる言い回しは使わず事実どおりに
          • 説明文の問いかけは動画の締めの問いかけと同じ(closing_question)

          競合調査のやり方(R2)

          • 競合を大手/新規/少登録者の高再生/低再生に分け、原則直近10本(必要なら30本)
          • 公開日・再生数・経過日数・登録者比・平均と中央値・上下各3本・冒頭・構成などを記録
          • 公開されていないCTRは推測で確定しない。取得できない値は「未確認」
          • 長尺はG0の前に同じ題材の先行動画を上位5本・下位5本調べる

          連続制作と利用枠

          G0はバッチで一括承認し、1本がG6まで終わると次の本へ自動で進む。本数の上限は決めず、Claudeの利用枠が続く限り制作。上限に達したら工程の状態を bin/kabu に残し、枠が戻ったら止まった所から再開する。

          納品のかたち

          1本ごとに「動画・表紙(ショートA/B、長尺A/B/C)・タイトル・説明文」を1セットで渡す。タイトルと説明文はそのまま貼れるテキスト。投稿はシステムでは行わず、荒木さんが判断する。

          実例: 「愛子さま25年の軌跡」(12/1お誕生日)

          長尺1本と、そこへ誘導するショート3本を同時に制作した流れです。

          制作番号内容公開想定点検で直したこと

          各段階で「決まりの確認係」「事実確認係」「当てっこ係」が差し戻し、直し係が直して再点検。たとえば宮中午餐の写真は、どなたが写るか説明文で確かめられず皇族方以外が大きく写るため使用をやめ、別の日の写真に「午餐の写真ではありません」と表示しました。
