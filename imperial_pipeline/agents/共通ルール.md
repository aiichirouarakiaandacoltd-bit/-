# 全サブエージェント共通ルール

**すべてのサブエージェントは、作業開始前に本ファイルを読むこと。**
本ファイルと個別エージェント定義が矛盾する場合、本ファイルを優先する。

---

## 1. チャンネルの軸

「公式事実で、静かな感動を。」

皇室を娯楽的な対立構造に利用しない。
視聴者の関心を引くことは必要だが、それを事実・敬意・権利より優先しない。

## 2. 視聴者

- 女性 約82％／65歳以上 約70％／55〜64歳 約18％
- 中心視聴者は55歳以上、特に65歳以上の女性
- **スマートフォン視聴を前提** とする

したがって：一文を短く、専門用語には短い説明を、日付は和暦（西暦）併記、
画面の文字は大きく、情報量は少なく。

## 3. 絶対禁止事項（全成果物に適用）

<!-- SCAN:OFF -->
1. 皇族方のAI生成顔
2. 皇族方の顔の合成、変形、若返り、老化
3. ディープフェイク
4. 本人が発言していない言葉の創作
5. 「きっとこう思われた」「胸の内では」などの内心断定
6. 根拠のない不仲、対立、冷遇、優遇の断定
7. 出典不明の人物写真
8. 使用条件が不明な写真や映像を「使用可能」と断定すること
9. 報道機関の写真や映像を無条件で使用可能と判断すること
10. SNS投稿画像の無断使用を推奨すること
11. 公式発表より週刊誌やまとめサイトを優先すること
12. 日付、人物、場所、肩書を推測で補完すること
13. 「要確認」を隠して完成扱いすること
14. 出典URLが存在しないのに架空URLを作ること
15. 一般イメージ画像を実際の公務写真のように扱うこと
16. 視聴者を欺くサムネイル
17. 特定人物への攻撃や侮辱
18. チャンネル内の過去動画とほぼ同じ台本の再生成
19. 他チャンネルの台本、タイトル、サムネイルの丸写し
20. 自動生成した内容を無確認でYouTubeへ公開すること
21. できない処理を、できたと報告すること
<!-- SCAN:ON -->

**21番は特に重要である。** 調査できなかったものを調査できたことにしない。
確認できなかったものを確認済みにしない。生成できなかったファイルを生成したと言わない。

## 4. 情報源の優先順位

| 優先度 | 情報源 |
| --- | --- |
| 第1優先 | 宮内庁公式サイト・公式発表／国会・内閣府・政府機関／官報／皇室制度に関する法令・国会資料／公務先の公的機関や主催者の公式ページ／大使館・外国王室・国際機関の公式発表 |
| 第2優先 | NHK／全国紙／通信社／信頼性の高い報道機関／行事主催者の公式発表 |
| 第3優先 | 専門家の解説／書籍／信頼できる研究資料 |
| 補助的にしか使用しない | 週刊誌／芸能系メディア／個人ブログ／まとめサイト／SNS／YouTube動画／匿名投稿 |

**補助情報のみで事実を確定してはならない。**

## 5. 事実と表現の分類

すべての台本記述を次のいずれかに分類する。

| 分類 | 内容 | 台本での扱い |
| --- | --- | --- |
| A．確認済み事実 | 一次資料または信頼性の高い資料で確認できた内容 | 断定してよい |
| B．根拠付き解説 | 複数の事実から合理的に説明できる内容 | 断定せず、根拠を示した表現にする |
| C．演出・一般イメージ | 実際の出来事の記録ではない映像 | 「イメージ」であることを必ず明示する |
| D．使用不可 | 根拠がない、内心断定、権利不明、人物誤認の可能性 | 台本と指示書から除外する |

事実台帳（`research/05_事実台帳.csv`）の確認状態が
**「確認済み」または「複数資料で確認済み」でない内容を、台本で断定してはならない。**

## 6. 不明情報の扱い

推測で補完しない。次のタグを使う。

【未確認】【一次資料未確認】【権利条件要確認】【素材URL未取得】
【人物確認が必要】【日付確認が必要】【使用非推奨】【アクセス未確認】【サンプル・ダミーデータ】

- 未確認項目があっても、他の工程を止めない
- 承認用サマリーへ集約して報告する
- **空欄のまま放置しない。** 分からないならタグを書く

## 7. 敬称

`config/honorifics.yaml` の `use` 表記へ統一する。
`status: 要確認` の項目については、勝手に決めず、
承認用サマリーの判断項目として荒木愛一朗へ提示する。
公式文書の引用内は原典の表記を優先する（統一の対象外）。

## 8. 素材の基本方針

**「使えそうな素材を探して権利を判定する」のではない。**
**「使用可能と確認済みの素材ライブラリ（`library/approved_materials.csv`）の範囲内で設計する」。**

- ライブラリに無い素材は、原則として使用可能と判断しない
- 公式サイトに掲載されているという理由だけで使用可能と判断しない
- 報道写真・報道映像は原則「使用非推奨」
- 不足する場合は **「素材不足」と明記** し、自社作成図解・テロップ中心画面・地図・年表で代替する
- 素材が足りないことを隠して、それらしい候補を書かない

## 9. ネットワークが使えない環境での動作

`ENVIRONMENT.md` の `network_status` を確認すること。
アクセスできない場合：

- 工程3の調査は **テンプレート生成のみ** とする
- 全項目へ【アクセス未確認】を付す
- **架空の調査結果を作らない**
- 「調べた結果こうだった」と書かない。「この環境では確認できなかった」と書く

## 10. 出力時の共通作法

1. 既存ファイルを開き、**該当セクションのみを埋める**。ファイル全体を作り直さない
2. `<!-- MACHINE_BLOCK:...:START -->` 〜 `END` の中は **書き換えない**（Pythonが管理する）
3. `<!-- INTERNAL:START -->` 〜 `END` は内部資料であり、最終版から自動除去される
4. 冒頭の生成日時の行を消さない
5. `sample_mode: true` のプロジェクトでは、冒頭のサンプル表示を消さない
6. 文字コードは UTF-8、CSVは utf-8-sig、改行は LF
7. 作業後に必ず次を実行し、機械検出の結果を確認する

```
python run_imperial_pipeline.py projects/<slug>/input/project_input.yaml --stage check
```

## 11. 役割分離の原則

**自分が書いたものを、自分で合格にしない。**

- `imperial-writer` が書いた台本は、`imperial-fact-checker` と
  `imperial-safety-reviewer` が別途検証する
- `final-auditor` は、他のエージェントの成果物を突合する立場であり、
  自分で台本を書き直さない（指摘して差し戻す）
- 「問題ありません」と報告する前に、**実際にファイルを読んで確認したか**を自問する
