# 速報ショートの型(縦型・45〜60秒)

荒木さん承認 2026-11-27。宮内庁に新しい写真ページ・ご日程・おことばが載ったら早く気づき、この型で数時間で縦型ショートを1本出す。
決まりは docs/production_rules.md のまま(第1-2章・第1-4章・第1-6-3章・第4章・第4-3章・第5章・第9章)。この型は「速く出すための順番と雛形」で、検査(G1〜G6)は省かない。

- **荒木さんの承認は G0 の1回だけ**(第2章)。G0 後は承認を求めず、表紙まで完成させて報告する。
- 条件付きで承認済みの企画(例: BATCH-20261127:R2)は、見張りの報告で条件を満たしたら G0 済みとして G1 から始める(`bin/kabu new --from-batch BATCH-…:R2`)。
- **事実は宮内庁の原文だけ**。報道だけで分かる出来事・発言は使わない。宮内庁に載っていない出来事は速報にしない。

---

## 0. 速報にする条件(見張りの報告 data/watch_report.md から選ぶ)

| 見るもの | 条件 |
|---|---|
| 写真 | その行事ページに**提供者表記なし**の写真が5枚以上(表記ありは表紙に使わない・本編も原則使わない)。主役の方の**笑顔の寄り**に切り抜ける写真が1枚以上 |
| 答え | 冒頭の疑問の答えが、宮内庁の本文・写真説明・おことばの一字一句で言える |
| 主役 | 1本に主役は1人(または両陛下・同妃両殿下など1組)。皇族方どうしを比べない |
| 場面 | 1つの行事の1つの瞬間・1つの言葉に絞れる(第1-4章「1本＝1場面」) |
| 避けるもの | 献花・慰霊・被災地お見舞いを明るい題名にしない。揶揄・対立・内心の断定になる切り口は不採用(第1-2章) |

おことばだけのページ(写真なし)は、同じ行事の写真ページが載るまで待つ。待てない時は G0 で「写真は同じ方の近年の確認済み写真(撮影日を表示)」と書いて承認をもらう(第4章)。

---

## 1. G0 で荒木さんに出すもの(この5行だけ。15分で作る)

```
【速報候補】<行事名>(<行事の日>・宮内庁 掲載 <掲載日>)
題名案: 【<主役>】<短い疑問・…で止める> <具体語> #<主役> #<行事/地名> (99字以内・#2〜4個)
疑問と答え: <疑問>？ → <答え>(宮内庁の原文「…」<URL>)
写真: <枚数>枚(表記なし <n>枚)。冒頭=<ファイル名>(<主役>の笑顔の寄り)。表紙=<ファイル名>
5要素: 疑問/事実(宮内庁 <URL>)/物語/比較(事実×事実)/解説 を各1行。型=A型・解説型 50秒
```

承認の返事をもらったら `bin/kabu new --topic "<行事名>" --subject "<主役>"` → `bin/kabu approve G0 --note "速報"`。

## 2. 台本の雛形(12〜16場面・1場面1文・です・ます調)

尺の目安は 45〜60秒(上限75秒)。締めくくりを削って尺に収めない。削るのは本編の寄り道(第1-4章)。

| # | 秒の目安 | 役割 | ナレーション(雛形) | 写真の当てはめ |
|---|---|---|---|---|
| 1 | 0〜2 | **冒頭(笑顔の寄り)** | (声は2の文から。字幕は疑問の短い形を出す) | **主役の笑顔の寄り**。正面〜斜め前・目線が下がっていない写真を顔中心に切り抜く(第9章①) |
| 2 | 2〜6 | 疑問 | 「<日付>、<場所>で<主役>が<した/伝えられた>〇〇とは？」 | 同じ行事の引き(会場・相手と一緒) |
| 3〜6 | 6〜25 | その瞬間の事実(2〜4場面) | 宮内庁の本文・写真説明の言い換え1文ずつ。「〜になりました」「〜をお聞きになりました」 | ナレーションの中心の言葉が写る写真(第4-3章)。引き→寄りを交互に |
| 7 | 25〜29 | 前置き | 「<主役>が<…>〇〇とは、何だったのでしょうか。」(冒頭の問いの言い直しは1回だけ) | 主役の寄り(冒頭と別の写真) |
| 8〜9 | 29〜40 | 答え | 「答えは、<…>です。」+ 原文の引用1〜2か所(かぎかっこ内は一字一句) | 答えの瞬間そのものの写真(なければ同じ物・場所) |
| 10 | 40〜44 | 比較 or 解説(どちらか1つ) | 時間の比較(前回・初めて等)か、制度の解説(「〜と言えるかもしれません」と分析と分かる言い方) | 比べる相手の写真(撮影日を表示) |
| 11 | 44〜47 | ①まとめ | 疑問の答えを一文で言い直す | 主役の寄り(未使用の写真) |
| 12 | 47〜50 | ②意味づけ | 「〜だったのかもしれません。」(事実を足さない) | 行事の雰囲気が伝わる引き |
| 13 | 50〜55 | ③問いかけ・④お願い | 「皆さまの心に残ったのは、<選んで答えやすい問い>ですか。ぜひコメントで、お聞かせください。」 | 主役の穏やかな写真+約2秒の余韻 |

台本の点検(決まりの確認係・第1-6-3章の右列):
- 相手の内心・反応(「驚いた」「感動」「絶賛」)を書いていない。発言は宮内庁の原文の一字一句だけ。
- 報道・SNS・海外の反応を使う時は出典(媒体・日付・URL・原文)付き。ただし速報では原則使わない(宮内庁原文だけで作る)。
- 「答えは〜」の前に前置きがある。問いかけは皇族方の比較を聞かない。説明文の `closing_question` と同じ。

## 3. 写真の当てはめ方

1. 見張りの報告の行事ページを `bin/kabu run images --pages <URL> [<子ページURL>…]` で集める(→ ledger.csv)。提供者表記のある写真(「写真：〇〇県」等)は台帳に残しても使わない。
2. 写真ごとに「写っている方・瞬間」を写真説明で確かめる。説明が1つだけの写真は「ページ説明文(要目視)」→ 当てっこ係が目視確認(第3章)。
3. 先に**冒頭と表紙の写真**を決める(同じ写真を使わない。表紙は直近の表紙・本編で使っていない写真。下向き・皇族方以外の人物が入る写真は不可・第9章②)。
4. 残りを場面に当てる。ナレーションの中心の言葉→その言葉が写る写真(第4-3章の優先順位)。`scenes.json` の `match` に理由を書く。
5. 縦型は**同じ写真は1回だけ**。写真が少ない時だけ、寄り・引きを変えて2回まで(隣に置かない・qa_rules の SHORT_REUSE2 に登録)。関係のない写真で埋めない。
6. 写真5〜7枚なら場面は11〜13に抑える(多様さ0.6以上: 異なる写真 ÷ カット数)。
7. `bin/kabu run focus` で主役の位置を登録(冒頭の寄りは顔が中央・ズーム2〜7%)。

---

## 4. 題名と表紙(第9章①②・第1-6-3章)

- 題名: `【<主役>】<疑問・「…」で止める> <地名・行事> #<主役> #<行事>`。答えを言い切らない。事実の範囲の言葉だけ。
  - 例: `【愛子さま】シンガポールの午餐会で、最後に伝えられた言葉は… #愛子さま #シンガポール`
- 表紙3段は題名の文言から流用。一番大きな中段に「その瞬間」「次の一言」「答えは…」など引きの語を使ってよい。赤・矢印・汗マーク・作られた台詞は使わない。
- 表紙は A・B の2パターン(第9章②)。`bin/kabu run thumb_render` → Canva。

## 5. 工程と目安時間(合計 約4〜5時間。G0 の返事待ちを除く)

| 工程 | 担当 | 目安 | 中身 |
|---|---|---|---|
| watch | 見張り(`bin/kabu run watch`) | 1分 | 新着・写真の枚数・提供者表記・おことば・条件付き企画の判定 → data/watch_report.md |
| G0 | 企画係 → **荒木さん承認(1回だけ)** | 15分+返事待ち | 上の「G0 で出すもの」5行 |
| G1 事実 | 事実確認係 | 30分 | 宮内庁原文で日時・場所・敬称・引用を照合 → facts.md |
| G2 素材 | 制作係・当てっこ係 | 30分 | `bin/kabu run images --pages …` → ledger.csv、要目視の確認 |
| G3 台本 | 台本係 → 決まりの確認係 | 45分 | 上の雛形で script.md・scenes.json → 採点 |
| 点検 | 当てっこ係 | 20分 | `bin/kabu run focus`(主役の位置) |
| G4 書き出し | 書き出し係 | 20分 | `bin/kabu run render` |
| G5 検査 | 確認係・当てっこ係 | 20分 | `bin/kabu run qa`・`bin/kabu run frames` |
| G6 表紙・説明文 | タイトル係・デザイナー・説明文係 | 45分 | 3段見出し・表紙A/B・説明文 → `bin/kabu run pub_check` |

G1〜G6 で不合格が出たら差し戻して直す(承認は求めない)。完成したら荒木さんへ完成報告(題名・表紙・G1で直した点)。公開は荒木さんが判断する。
